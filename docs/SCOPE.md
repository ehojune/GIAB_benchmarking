# GIAB 작업 범위와 완료 기준

2026-09-25 사용자 지시. 다른 문서의 미완료 표시나 옛 위임보다 이 기준을 먼저 따른다.

## 할 일

본래 목적은 **HG002/3/4 공개 숏·롱리드와 국내 4회사 자료를 우리 파이프라인으로 처리하고 GIAB 정답셋으로 비교**하는 것이다. 업체 숏리드는 기본분석 완료, 롱리드는 수령 대기다. 완료한 공개 비교군부터 비교하고 나머지 기본 run은 이어간다.

추가 의뢰인 **GIAB 자료 확보 → 필요한 기본 run → 간단 QC**도 마무리한다. 09-25 현재 카탈로그·매니페스트를 고정 명세로 삼는다. 새 release를 계속 찾거나 모든 빈칸을 새 기능으로 채우지 않는다.

## 여기까지 하면 완료

- 자료별 입력·샘플·플랫폼·산출물·pipeline/reference 버전을 한 목록에 남긴다. 미처리 항목은 `gap`, 동일 원본은 `duplicate`, 목적상 불필요한 단계는 `not-needed`, truth 부재는 `no-truth`로 이유와 함께 표시한다. 빈칸을 성공으로 바꾸지 않는다.
- 필요한 기본 run의 완료 로그, BAM/VCF 존재·읽기 가능 여부, coverage·mapping 등 간단 QC를 확인한다. 숏리드는 `__DONE__`와 `error_list.txt`, BAM 리드 수를 함께 본다.
- HG002/3/4 회사·공개 자료를 같은 플랫폼의 같은 파이프라인과 truth/영역으로 비교한다. 기존 hap.py/v4.2.1의 SNP·INDEL precision/recall/F1 표를 먼저 낸다. 이미 만든 SV 결과는 보존해 함께 요약한다.
- 추가 자료는 기본처리·QC로 닫는다. `no-truth` 자료에 새 somatic caller를 붙이는 일은 완료 조건이 아니다. checksum의 `NOREF`는 참조값 없음이며 검증 성공과 구분한다.

## 비용과 실행

GIAB 실행 담당은 한 명이다. 지금은 숏리드 담당이 최소 비교를 진행한다. 준비된 잡을 제출하면 대기하고 완료 시 결과만 수집한다. 기존 서버 잡과 원본·결과·작업 트리는 보존한다.

bioinfo-agent의 재사용 가능한 범용 개발은 별도 담당 한 명이 계속한다. GIAB 완료를 기다리게 하지 않으며, 개발 결과의 GIAB 재-vendor·somatic pilot·전장 확장은 보류한다.

새 에이전트, 반복 리뷰봇 호출, 상시 polling, 추가 caller·중복 run·원인 규명·구간별 연구·구조 통일·자동 HARVEST/Yuan PR은 시작하지 않는다. 실제 실행 실패나 핵심 비교 오류만 작게 고친다. 필요 범위를 넓힐 때는 먼저 사용자에게 범위와 비용을 알린다.
