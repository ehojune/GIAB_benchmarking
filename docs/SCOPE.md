# GIAB 작업 범위와 완료 기준

2026-09-25 사용자 지시. 다른 문서의 미완료 표시나 옛 위임보다 이 기준을 먼저 따른다.

## 할 일

본래 목적은 **HG002/3/4 공개 숏·롱리드와 국내 4회사 자료를 우리 파이프라인으로 처리하고 GIAB 정답셋으로 비교**하는 것이다. 업체 숏리드는 사용자 정본에 맞춰 4회사 모두 다시 준비하고 germline을 제출했다. 분석 완료가 아니며, 교정한 run이 끝나면 완료된 공개 비교군과 비교한다. 업체 롱리드는 수령 대기다.

추가 의뢰인 **GIAB 자료 확보 → 필요한 기본 run → 간단 QC**도 마무리한다. 09-25 현재 카탈로그·매니페스트를 고정 명세로 삼는다. 새 release를 계속 찾거나 모든 빈칸을 새 기능으로 채우지 않는다.

## 여기까지 하면 완료

- 자료별 입력·샘플·플랫폼·산출물·pipeline/reference 버전을 한 목록에 남긴다. 미처리 항목은 `gap`, 동일 원본은 `duplicate`, 목적상 불필요한 단계는 `not-needed`, truth 부재는 `no-truth`로 이유와 함께 표시한다. 빈칸을 성공으로 바꾸지 않는다.
- 필요한 기본 run의 완료 로그, BAM/VCF 존재·읽기 가능 여부, coverage·mapping 등 간단 QC를 확인한다. 숏리드는 `__DONE__`와 `error_list.txt`, BAM 리드 수를 함께 본다.
- HG002/3/4 회사·공개 자료를 같은 플랫폼의 같은 파이프라인과 truth/영역으로 비교한다. 기존 hap.py/v4.2.1의 SNP·INDEL precision/recall/F1 표를 먼저 낸다. 이미 만든 SV 결과는 보존해 함께 요약한다.
- 추가 자료는 기본처리·QC로 닫는다. `no-truth` 자료에 새 somatic caller를 붙이는 일은 완료 조건이 아니다. checksum의 `NOREF`는 참조값 없음이며 검증 성공과 구분한다.

## 비용과 실행

숏리드는 최신 사용자 지시로 gd1~4 전체를 공통 백업 후 원래 SET_ID에 재구성하고 서버 엑셀을 교정해 실제 제출했다. 네 회사 모두 ID 순번 1–3은 KOR-101/102/103, 4–6은 HG002/3/4다. 입력은 `outcome/<20자리 ID>/<ID>_1.fastq.gz`·`<ID>_2.fastq.gz` 링크 한 쌍이다. 이전 업체 분석·비교 결과는 역사자료로 보존하고 새 실행의 캐시로 쓰지 않는다. 같은 파일·잡은 한 담당이 맡는다.

bioinfo-agent 범용 개발은 별도로 진행한다. **somatic 전장은 사용자의 직접 지시로 PacBio 담당이 진행한다.** PacBio가 입력·통합·서버 실행, bioinfo가 범용 코드·검증을 맡고 HG002/3/4 기본 비교의 완료 조건과는 분리한다.

09-25 21:44 사용자 지시: **국통바빅 재시도는 `regermline`**을 쓴다. 반복 실패한 Manta 중간 폴더는 기존 동일 세트 잡이 끝난 뒤 실행 경로에서 비우고 재개한다. 원자료·정상 BAM·완료 결과와 실패 근거는 보존한다.
