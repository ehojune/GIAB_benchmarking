# HG002 R10 — v5.0q smvar 로 v4.2.1 밖을 직접 센다 (2026-09-24)

[2026-09-22 R10 채점](2026-09-22-ont-r10-benchmark.md) §5 가 남긴 질문 — **DeepVariant 가 v4.2.1 구간 밖에서
진짜 변이를 버리는가** — 에 truth 로 답한다. 9/23 의 ts/tv 로는 못 가렸던 것이다(구간 밖 truth 가 없었다).

잡 156640 (hap.py, Clair3·DV, exit 0, 38.8분, maxvmem 25.1 GB, shepherd-1-8).
truth `HG002_GRCh38_v5.0q_smvar`(T2T-Q100 유래). 층은
[`64_v5q_strata.py`](../../phase2_ont/scripts/64_v5q_strata.py), 채점은
`BENCH_TRUTH_VER=v5.0q BENCH_STRAT_TSV=... 60_benchmark.sh`.

## 1. 층

v5.0q 는 v4.2.1 보다 넓다. **한 번의 채점 안에서** `hap.py --stratification` 으로 세 층을 셌다 — v5.0q 결과에서
v4.2.1 결과를 빼면 두 truth 의 차이가 섞이기 때문이다(9/23 순차분 2.18 과 같은 함정).

| 층 | 크기 | 뜻 |
|---|---:|---|
| `v5q_and_v421` | 2,496.2 Mb (91.1%) | 겹침 — **대조용** |
| `v5q_not_v421` | 83.1 Mb (3.0%) | v4.2.1 이 덮는 염색체(chr1~22) 안에서 v5.0q 에만 있는 곳 — **답** |
| `v5q_other_chrom` | 160.1 Mb (5.8%) | v4.2.1 이 아예 안 덮는 chrX · chrY |

세 층 합 = v5.0q 전체 2,739,407,815 bp (스크립트가 대조). v4.2.1 에만 있고 v5.0q 가 뺀 46.0 Mb 는 여기서 안 센다.

**네 칸 전부 0.001 안에서 같다.** 두 truth 가 겹치는 곳에서 일관되므로 "밖" 층의 숫자를 두 truth 차이로
설명할 여지가 작다. 이 대조가 크게 어긋났다면 아래 결론을 쓰지 않았을 것이다.

## 3. 답 — DV 는 v4.2.1 밖에서도 진짜 변이를 덜 놓친다

`v5q_not_v421` 층, PASS:

| | caller | TP | FN | FP | recall | precision | **F1** |
|---|---|---:|---:|---:|---:|---:|---:|
| SNP | Clair3 | 231,408 | 25,664 | 28,014 | 0.900 | 0.890 | 0.895 |
| SNP | **DV** | 236,288 | **21,284** | **13,973** | **0.917** | **0.943** | **0.930** |
| INDEL | Clair3 | 144,493 | 172,554 | 108,324 | 0.456 | 0.602 | 0.519 |
| INDEL | **DV** | 161,520 | **155,554** | **48,526** | **0.509** | **0.788** | **0.619** |

| DV − Clair3 | FN | FP |
|---|---:|---:|
| SNP | −4,380 (**−17.1%**) | −14,041 (−50.1%) |

**DV 가 recall 과 precision 둘 다에서 이긴다.** 9/22 의 의심은 "DV 가 구간 밖에서 진짜 변이를 버린다" 였는데,
truth 로 세니 반대다 — DV 가 **더 많이 찾고**(FN 이 적고) **덜 헛부른다**(FP 가 절반 이하).

→ **"ONT R10 기본 caller = DeepVariant" 는 v4.2.1 밖의 어려운 영역에서도 선다.** 9/22 에는 "구간 안에서만
검증된 결정" 으로 한정해 뒀던 것이다.

### 어려운 영역은 정말 어렵다

| DV SNP | 0.9995 | 0.930 |
| DV INDEL | 0.9375 | **0.619** |

v4.2.1 이 "아직 못 믿겠다" 고 빼 둔 구간답다. INDEL 은 절반 가까이 놓친다(recall 0.51).

## 4. chrX·chrY 층은 caller 성능이 아니다

`v5q_other_chrom` 층의 F1 은 0.054~0.065 로 두 caller 모두 무너진다. 그런데 모양이 이상하다:

| | 전체 − TP | FN | FP | FP / FN |
|---|---:|---:|---:|---:|
| Clair3 SNP | 81,973 | 81,973 | 81,896 | 0.999 |
| DV SNP | 81,953 | 81,953 | 81,635 | 0.996 |

**FN 과 FP 가 거의 같다.** 변이를 못 찾은 게 아니라, **같은 자리를 부르되 유전형이 어긋나** 한 번은 FN, 한 번은
FP 로 세인 모양이다. HG002 는 남성이라 chrX·chrY(PAR 밖)의 truth 는 반접합(haploid)인데, 파이프라인의 두
caller 는 이배체 유전형을 낸다. 맞은 6.5% 는 PAR 처럼 이배체가 맞는 구간일 것으로 보인다(미확인).

**확인하려면** hap.py 에 `--squash-ploidy` 를 주거나 extended.csv 의 `FP.gt`(유전형 불일치 FP) 열을 보면 된다.
여기선 하지 않았다 — 답할 질문(상염색체 어려운 영역)과 무관하고, 이 층을 따로 떼어 둔 목적이 오염을 막는
것이었다. **이 층을 "밖" 에 섞었으면 위 결론을 흐렸을 것이다** — 64 를 자체 리뷰할 때 가른 이유다.

`Subset=*`(v5.0q 전체) 행도 이 층에 끌려 내려가 있어(DV INDEL F1 0.805) **대표값으로 쓰지 않는다.**

## 5. 9/23 의 ts/tv 해석과 대조

9/23 `63_caller_diff_regions.sh` 는 구간 밖 단독 콜의 ts/tv 가 Clair3 0.87 · DV 0.67 이라 "둘 다 공유(1.31)보다
낮다" 까지만 말하고 FP 로 분류하지 않았다. 방향 하나 — "Clair3 단독이 DV 단독보다 덜 FP 같다" — 는 크기 없이
적어 뒀다.

이번 truth 결과는 **그 방향과 맞지 않는다.** v4.2.1 밖 83 Mb 에서 Clair3 의 FP 는 DV 의 두 배 이상이다.

**다만 엄밀한 반례는 아니다.** 두 분석은 대상이 다르다:

| | 9/23 (63) | 9/24 (v5.0q 층화) |
|---|---|---|
| 범위 | v4.2.1 BED 여집합 전체 — 성염색체·미배치 contig 포함 | v4.2.1 염색체 안에서 v5.0q 가 덮는 83 Mb |
| 집합 | 한 caller 만 부른 **단독** 콜 | 한 caller 의 **전체** FP (공유 콜 속 FP 포함) |

그래서 "ts/tv 방향이 틀렸다" 고까지는 말하지 않는다. 말할 수 있는 것은 이것이다 — **ts/tv 가 가리킨 방향을
truth 가 뒷받침하지 않았다.** ts/tv 는 집합에 어떤 치환이 섞였는지를 재지 FP 가 얼마나 있는지를 재지 않으니,
방향이라도 FP 판정의 근거로 쓰지 않는 편이 맞다. 9/23 에 그 방향을 "크기는 못 잰다" 로 한정해 둔 것은 옳았고,
이번 결과는 그 한정을 방향에까지 넓히라는 경고로 읽는다.
